# Liella! キャスト出演予定登録ツール（MVP）

Liella!キャストの出演情報（公式サイト・X・YouTube・番組サイト等）を見つけたその場で、スマートフォンからGoogle Apps Script (GAS) のWebフォームに入力し、Googleカレンダーへ登録するための個人用ツールです。

Google Sheetsもデータベースも使いません。フォーム入力 → サーバー側検証 → Googleカレンダー登録、というその場限りのシンプルなフローです。予定の閲覧・通知・編集はGoogleカレンダー側の機能をそのまま利用します。

## できること

- スマートフォン（主にiPhone）から開けるWebフォームに出演情報を入力し、その場でGoogleカレンダーへ登録
- 出演者の複数選択、時間指定/終日イベントの切り替え
- 会場（任意）はGoogleカレンダーの「場所」欄に登録され、カレンダーアプリの地図・ナビ連携が使える
- ラジオ番組のような定期予定向けに「毎週」の繰り返し登録（回数指定）に対応
- 終了時刻が未入力の場合は開始時刻+既定の所要時間（既定60分）を仮の終了時刻として補完
- サーバー側での入力チェック（不正な入力はフィールドごとにエラー表示、登録は行わない）
- 送信ボタンの二重送信対策（送信中はボタンを無効化）
- 登録成功後に「同じ内容でもう1件登録（時間だけ変更）」ボタンで、出演者・タイトル等はそのまま時刻だけ空にして続けて登録可能（ファンミーティングの昼の部/夜の部など、同じイベントで時間帯違いの予定を続けて登録するケース向け）

## ファイル構成

```
liellacalender/
├── README.md
├── .clasp.json.example   # clasp設定のテンプレート（実際のscriptIdは各自で設定）
├── .claspignore
└── src/
    ├── appsscript.json     # GASマニフェスト（webapp設定・Calendarスコープ・Asia/Tokyo）
    ├── Config.js           # キャスト一覧・カテゴリ・Calendar ID・デフォルト所要時間などの設定値
    ├── Validator.js        # フォームデータのサーバー側検証
    ├── EventFactory.js     # 検証済みデータ → Calendarイベント用データへの変換（タイトル整形・終了時刻補完）
    ├── CalendarService.js  # Googleカレンダーへの新規イベント登録（時間指定/終日）
    ├── Code.js             # doGet（フォーム表示）+ submitEvent（登録処理の唯一の入口）
    └── index.html          # フォームUI（HTML/CSS/JS）
```

### 各ファイルの役割となぜこの構成にしているか

- **Config.js**: キャスト一覧・カテゴリ・登録先カレンダー・デフォルト所要時間・タイトル短縮しきい値を1箇所に集約。キャストの増減や運用ルールの変更をここだけの修正で完結させるため。
- **Validator.js**: フォームの形に依存する検証だけを持つ。クライアント側のチェックはあくまで操作性のための補助であり、サーバー側の検証だけを信用する（クライアントを経由しない直接呼び出しでも不正なデータが登録されないようにするため）。
- **EventFactory.js**: 検証済みデータをCalendar API向けの形（タイトル・説明文・日時）に変換するだけを担当。Calendar APIの呼び出し方法を知らない。将来キャスト別の色分けなどを追加する場合もこのファイルだけを触ればよい。
- **CalendarService.js**: Calendar APIの呼び出し（時間指定/終日イベントの作成、Calendar IDの解決）だけを担当。他のファイルはCalendarAppを直接触らない。
- **Code.js**: `doGet`でフォームを表示し、`submitEvent`でValidator→EventFactory→CalendarServiceの順に呼び出す。クライアントから呼べる関数はこの`submitEvent`だけに絞ってある。

## セットアップ手順

### 1. clasp をセットアップする

```bash
npm install -g @google/clasp
clasp login
```

初回のみブラウザでGoogleアカウントの認証を行います。

### 2. 新規GASプロジェクトを作成する

Webアプリ用に新しいスタンドアロンのGASプロジェクトを、リポジトリのルートで作成します。

```bash
clasp create --type webapp --title "Liella! キャスト出演予定登録" --rootDir src
```

これによりルートに `.clasp.json` が生成されます（`rootDir: "src"` が設定されているはずです）。生成されなかった場合や内容を作り直したい場合は、`.clasp.json.example` をコピーして手動で編集してください。

```bash
cp .clasp.json.example .clasp.json
```

```json
{
  "scriptId": "作成したスクリプトID",
  "rootDir": "src"
}
```

※ `.clasp.json` は個人のIDを含むため `.gitignore` 済みです。

### 3. コードをGASへ反映する

```bash
clasp push
```

### 4. Config.js を自分用に調整する

`src/Config.js` を開き、以下を必要に応じて編集します。

- `CAST_LIST`: 実際のLiella!キャスト一覧に合わせて確認・修正してください（本リポジトリのデフォルト値は目安です）
- `CATEGORY_LIST`: カテゴリの追加・変更
- `CALENDAR_ID`: 特定のカレンダーに登録したい場合はそのCalendar IDを設定（空文字のままならGoogleアカウントのデフォルトカレンダーに登録されます）
  - Calendar IDはGoogleカレンダーの「設定と共有」→ 対象カレンダーの詳細 →「カレンダーの統合」内の「カレンダーID」で確認できます
- `DEFAULT_EVENT_DURATION_MINUTES`: 終了時刻未入力時に使う仮の所要時間
- `MAX_CAST_LABEL_LENGTH`: タイトルの出演者ラベルを短縮する文字数のしきい値
- `RECURRENCE_OPTIONS`: 繰り返し登録の選択肢。現状は「毎週」のみだが、`{ value: 'biweekly', label: '隔週', ruleType: 'weekly', interval: 2 }` のように追加すれば「隔週」「毎月」なども増やせる（`ruleType` に対応する変換ロジックを `CalendarService.js` の `RECURRENCE_RULE_BUILDERS_` にも追加する必要がある）
- `MAX_RECURRENCE_COUNT`: 繰り返し回数の入力上限（誤操作で大量のイベントを作成しないための上限）

編集後は `clasp push` に加えて、後述の「コード変更をデプロイ済みURLへ反映する」も忘れずに実行してください（`push` だけではデプロイ済みの `/exec` URLには反映されません）。

### 5. 必要な権限

このツールはGoogleカレンダーへの書き込み権限（`https://www.googleapis.com/auth/calendar`）を使用します。GAS組み込みの`CalendarApp`サービスは`calendar.events`スコープでは不十分で、この広めのスコープが必要です。独自の認証システムは持たず、Webアプリへのアクセス自体をあなたのGoogleアカウントに限定する設定（後述）と、GAS自体の権限承認フローに委ねています。

### 6. Webアプリとしてデプロイする

```bash
clasp deploy
```

初回デプロイ時、GASエディタ（`clasp open`で開けます）側で以下を確認してください。

- 「デプロイ」→「新しいデプロイ」→ 種類の選択で「ウェブアプリ」を選ぶ
- **実行するユーザー**: 「アクセスしているユーザー」（`USER_ACCESSING`。あなた自身のGoogleカレンダー権限で動作します）
- **アクセスできるユーザー**: 「自分のみ」（`MYSELF`。他人はアクセスできません）
- デプロイ後に発行される **WebアプリのURL** を控えてください（`https://script.google.com/macros/s/.../exec` の形式）

初回アクセス時にGoogleの権限承認ダイアログが表示されます。「権限を確認」→ 自分のGoogleアカウントを選択 →「詳細」→「(安全ではないページに移動)」→ 許可、の順で進めてください。

### 7. iPhoneからアクセスする

1. iPhoneのSafariで、控えたWebアプリのURLを開く
2. 自分のGoogleアカウントでログインを求められたらログインする
3. フォームが表示されればOK

### 8. ホーム画面への追加

1. SafariでWebアプリを開いた状態で、共有ボタン（下部の四角と矢印のアイコン）をタップ
2. 「ホーム画面に追加」を選択
3. ホーム画面のアイコンからワンタップで開けるようになります

### 9. コード変更をデプロイ済みURLへ反映する（重要）

`clasp push` はGASプロジェクトにコードを送るだけで、すでに発行済みの `/exec` URL（デプロイ済みバージョン）には自動反映されません。`Config.js` を直したときなど、変更をスマホの画面に反映したい場合は必ず以下の手順で**既存デプロイを更新（redeploy）**してください（URLは変わりません）。

```bash
# 1. コードを送る
clasp push

# 2. デプロイIDを確認する（初回のみ。以降は同じIDを使い回せばよい）
clasp deployments

# 3. 該当のデプロイIDを指定して更新する
clasp redeploy <デプロイID> --description "変更内容のメモ"
```

`clasp deployments` の実行結果には `@HEAD` のテスト用エントリと、`@1` `@2` のような番号付きの本番デプロイが表示されます。スマホで使っているURLに対応するのは番号付きの方なので、そのIDを `redeploy` に渡してください。

## 動作確認方法

1. 出演者を1人選び、タイトル・カテゴリ・日付・時間指定（開始/終了時刻）を入力して登録し、正しいタイトル・日時・説明欄でGoogleカレンダーに反映されることを確認する
2. 出演者を複数選んで登録し、タイトルが `【A・B】タイトル` の形で連結されることを確認する（出演者ラベルが長い場合は `【A他N名】タイトル` に短縮されることも確認する）
3. 終日イベントとして登録し、Googleカレンダー上で終日イベントとして表示されることを確認する
4. 終了時刻を空欄のまま時間指定イベントを登録し、開始時刻+デフォルト所要時間（既定60分）が終了時刻として設定されることを確認する
5. 出演者未選択・タイトル未入力のまま送信し、該当フィールドにエラーメッセージが表示され、登録が行われないことを確認する
6. 送信ボタンをタップした瞬間にボタンが無効化され「登録中…」と表示されること、完了後に再度有効化されることを確認する
7. 登録成功後、日付は保持されたまま他の項目がリセットされることを確認する
8. 「繰り返し」を「毎週」にして回数を指定して登録し、Googleカレンダー上でその回数分の繰り返し予定として登録されることを確認する（1件ずつではなく、同じイベントの繰り返しとして表示される）
9. 「繰り返し」を「毎週」にしたまま繰り返し回数を空欄または0以下で登録し、エラーが表示されて登録されないことを確認する

## よくあるエラーと対処方法

| 症状 | 原因・対処 |
|---|---|
| Webアプリを開くと「このアプリにアクセスできません」等が表示される | デプロイ設定の「アクセスできるユーザー」が自分のGoogleアカウントになっているか確認する。別のGoogleアカウントでログインしていないかも確認する |
| 権限承認画面から進めない | 「詳細」→「(安全ではないページに移動)」のリンクが表示されているはずなので、そこから進む（未検証アプリの警告は自分専用アプリのため想定内） |
| 登録時に「Config.CALENDAR_ID で指定されたカレンダーが見つかりません」エラーが出る | `Config.js` の `CALENDAR_ID` が正しいか、そのカレンダーへのアクセス権があるか確認する。空文字に戻せばデフォルトカレンダーに登録される |
| フォームを直しても反映されない | `clasp push` はしたが `clasp redeploy <デプロイID>` を実行していない可能性が高い。「9. コード変更をデプロイ済みURLへ反映する」の手順を実行する |
| 出演者一覧・カテゴリが古いまま | `Config.js` を編集後、`clasp push` → `clasp redeploy <デプロイID>` の両方を実行する |

## 今後の拡張予定（MVP後）

- URLや文章を貼り付けるとAIが出演者・タイトル・日時等を抽出し、フォームへ自動入力（最終登録は必ず人間が確認してから行う設計を維持する）
- Liella!公式サイト・キャスト公式サイト・YouTube・RSS等からの情報収集
- 収集した「見つかった情報」と「登録済みの確定予定」を分離管理する必要が出た段階でのDB/Sheets導入検討
- 一般公開を見据えたユーザー管理・OAuth・ICS購読・キャスト別フィルタ等（現時点では未着手）

これらを追加する場合も、`Validator` → `EventFactory` → `CalendarService` の経路はそのまま利用できるように設計してあります。例えばAI抽出機能を足す場合は、抽出結果を `submitEvent` と同じ形のオブジェクトに変換する新規モジュールを1つ追加するだけで組み込めます。
